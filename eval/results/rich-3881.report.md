## Summary

_Written by the model at report time; everything else in this report is generated from recorded state._

On merge, PromptBase.on_validate_error prints validation errors with markup=True, so a Console(markup=False) no longer shows literal [prompt.invalid] tags for Confirm, Prompt (choices), IntPrompt, FloatPrompt and custom InvalidResponse messages; a CHANGELOG entry was added. Verified by five new red-then-green tests in tests/test_prompt.py plus two regression guards (Text-message InvalidResponse unchanged, default Console output identical), and by the independent verifier's three tests showing the prompt.invalid style is actually applied (not just stripped), that emoji is not forced on, and that rich.markup.escape() still protects literal brackets. Nothing was only eyeballed; the whole suite passes (941 passed). One behavioural consequence to know before merging: a user on a markup=False console who raises InvalidResponse with unescaped brackets such as 'expected [a-z]' will now have that bracket text consumed as a style tag and must call rich.markup.escape(); the changelog line does not mention this.
