## Summary

_Written by the model at report time; everything else in this report is generated from recorded state._

On merge you get a one-line behaviour fix in rich/text.py: Text.wrap() now skips its line.rstrip_end(width) pass when the line is both no-wrap and overflow="ignore", i.e. when the line will never be shortened to the console width, so soft-wrapped text keeps the trailing whitespace (and the background colour painted on it) that issue #3841 reported as missing. The condition deliberately keys on 'this line is never cropped' rather than on no_wrap alone, so no_wrap with overflow="crop" or "ellipsis" still truncates to width exactly as before; a CHANGELOG entry was added and nothing else changed. Verified by tests: the issue's exact 89-cell reproduction at width 80, the console-level soft_wrap=True and per-call print(soft_wrap=True) paths, Text.wrap() directly, multi-space and whitespace-only trailing runs, the style span actually covering the kept space, and guards that hard wrapping never exceeds width and that crop/ellipsis still truncate — 955 tests pass, up from a 932-test clean baseline, with no existing test changed or weakened. Not fixed and worth knowing before you merge: the independent verifier found that Lines.justify in rich/containers.py rstrips each line before truncating, so printing soft-wrapped text with justify="center" or "right" still loses the trailing background — that path is outside this fix and is pinned by a test that records today's lossy output rather than failing. Also pre-existing, not a regression: Console._collect_renderables drops a Text instance's own no_wrap/overflow attributes, so the fix is reached via the console/print keywords, not via Text(..., no_wrap=True, overflow="ignore").
