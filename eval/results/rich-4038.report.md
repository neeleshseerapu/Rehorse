## Summary

_Written by the model at report time; everything else in this report is generated from recorded state._

Inline code in Markdown tables now keeps its syntax highlighting. The reported one-line fix is in: TableDataElement.on_text mirrors TextElement.on_text, branching on isinstance(text, str) so a pre-highlighted Text keeps its per-token spans instead of being flattened by an in-place stylize(current_style). The independent verifier then caught that the same defect survived one level up for header cells — TableElement.__rich_console__ applied markdown.table.header over the whole cell after the highlight spans — so TableDataElement now records the offsets of highlighted runs and a new build_header() lays the header style around them with stylize and underneath them with stylize_before. Verified by tests that compare a cell's styled segments against the same code in a paragraph, for both body and header cells, plus links, multiple snippets per cell, whitespace-only code, the no-lexer default path, justification, and render idempotence; the full suite is 970 passed / 25 skipped / 0 failed with no changes to any frozen-output test. Worth knowing before merging: build_header is new public-ish surface on TableDataElement rather than a one-liner, and its layering is deliberately asymmetric — markdown.table.header's bold=False sits under markdown.code's bold=True for highlighted runs, which is unobservable with real pygments themes (they set bold on every token) but is a judgement call you may want to eyeball.
