## Summary

_Written by the model at report time; everything else in this report is generated from recorded state._

On merge you get the fix for the reported bug: a Live whose renderable produces zero lines (an empty Group, or one that shrinks to empty) no longer leaves a blank line behind on exit, with or without transient=True. The cause was that Live.stop() unconditionally emitted a terminating newline via console.line() on a terminal, while transient cleanup (LiveRender.restore_cursor()) only undoes as many rows as the last render actually produced - zero for an empty renderable, so the newline survived. The fix adds a private LiveRender._rendered_height and skips that console.line() when nothing was rendered; no public API changed. Verified by test: the three previously-failing empty-render cases now pass, the independent verifier reproduced criteria 1 and 3 in their literal form with the default auto_refresh=True (the implementer's tests all used auto_refresh=False) and added shrink-to-empty and console.print-inside-an-empty-Live cases, and the exact-string assertions in test_growing_display, test_growing_display_transient and the two overflow tests are byte-for-byte unchanged; full suite 941 passed, 0 failed. Two things to know before merging: the fix also changes a dumb terminal with transient=True to stop emitting a bare newline (that path never renders anything, so _shape stays None - correct by the spec's own rule, but slightly wider than the reported terminal-only case), and two of the implementer's tests are weak - test_live_empty_grid_transient_cursor_balanced would pass on the unfixed code because an empty Table.grid() renders one line rather than zero (the spec's example was wrong), and test_existing_growing_display_output_unchanged just re-invokes four tests pytest already collects; neither weakens the fix, but both are worth deleting or rewriting.
