# Rehearsal report: Make `Traceback.extract` (and therefore `console.print_exception`) terminate on self-referential or cyclic exception chains instead of looping forever and exhausting memory.

## Summary

_Written by the model at report time; everything else in this report is generated from recorded state._

On merge you get a Rich that no longer hangs when rendering a traceback whose exception chain loops back on itself. Traceback.extract now keeps a set of the id()s of the exceptions it has already turned into a Stack and stops the walk when __cause__ or __context__ points at one of them, mirroring the _seen set in CPython's traceback.TracebackException; the issue's 'raise e from e' reproducer renders normally instead of eating RAM. This is verified by tests, not by inspection: thirteen new tests (six from the implementer, seven from the independent verifier) cover self-cause, self-context, two-exception cause/context/mixed cycles, a rho-shaped cycle whose repeat is not the head, unhashable exceptions in a cycle, end-to-end Console.print_exception output, and a regression guard that ordinary acyclic chains keep every stack, order and is_cause flag. Because unfixed code hangs rather than fails, these tests run the exercise in a memory- and time-bounded subprocess, so they fail rather than wedging the suite; the full suite is green at 864 passed, 25 skipped. Two things to know before merging: when __cause__ points at an already-visited exception the walk now falls through to __context__ (new behaviour that old Rich could never reach, and it matches what CPython's compact formatter does), and a BaseExceptionGroup member whose __cause__ is the enclosing group still raises RecursionError because the visited set is per-call and is not shared with the recursive per-member extract — that case was declared out of scope in the spec, behaves the same as before this change, and is pinned by a test so it cannot regress silently.
